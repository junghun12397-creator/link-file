# 프렙 카페 기능 요구사항 문서(FRD)

작성·갱신일: 2026-10-12  
상태: 추천 방향을 적용한 1차 기능 명세 완료. 2차 상세 설계는 후속 범위.

FRD는 사용자가 무엇을 하면 프로그램이 무엇을 처리하고, 화면·파일에 어떤 결과가 나오는지 정리한 문서다. 구현 기술이나 코드는 포함하지 않는다.

## 1. 근거와 확정 기준

검토 자료: `docs/01_PRD.md`, `design/artisan_ops/DESIGN.md`, `design/_1`~`_4`의 `code.html`·`screen.png`. HTML의 입력칸·버튼·계산 예제와 화면을 함께 대조했다.

사용자는 “추천대로 완성해줘”라고 요청했다. 이에 따라 메뉴 수익성은 식재료·포장재·결제수수료를 뺀 금액, 매장 손익은 여기에 운영비와 아래에서 정의한 폐기 손실을 반영하는 방향으로 정리했다. 나머지 1차 상세 기준도 핵심 흐름·기록 보존·중복 방지를 우선하는 추천 방향으로 구체화했다. 이 기준은 원본에 이미 합의되어 있던 정책이 아니라 이번 FRD에서 정리한 제품 기준이다.

PRD의 기능 범위와 단계 구분은 유지한다. 제공 시안에만 있는 POS 연동·로그인·보고서 출력·실제 주문 전송은 추가하지 않는다. PRD·원본·시안 파일은 변경하지 않았다. 시안이 없는 비용·재고·보관 기능은 구현 전 화면 설계에서 보완해야 하지만 기능 동작은 이 문서에서 정의한다.

## 2. 프로그램 개요와 자료

한 매장의 한 운영자가 날짜·메뉴·매장/포장별 판매 합계, 비용, 재고를 관리한다.

**판매 기록 입력 → 메뉴 수익성 확인 → 기간 손익·해당 시점 재료 잔량 확인 → 저장·백업**

1차: 판매·비용 입력/조회/수정/삭제, 메뉴 수익성, 일·월 실적·손익, 재료 입고·폐기·실제 재고 기록과 잔량, 기록 저장·전체 백업·복원.

2차: 엑셀 양식·가져오기, 주·분기·반기·연간 조회, 예상 손익, 부족 판단·발주량, 기초 정보 편집·추가 분석.

자료는 가상 매장의 2025-07-01~2026-09-18 마감 기록이다. 메뉴 8개·재료 11개·레시피 22개, 판매 6,112건·재고 1,515건·비용 3,560건이다. 영업달력은 2026-09-30까지이며 09-19~09-30은 미마감이다. 금액은 부가세 제외 원화, 재료 단위는 g·ml·개다. 엑셀과 JSON은 같은 기록이므로 초기 자료는 한 형식으로 한 번만 반영한다. 월비용계획과 일별 비용기록도 같은 비용이다.

판매 건수는 주문 수가 아니다. 날짜 수와 영업일 수도 다르다. 화면에서 주문 건수·객단가 또는 영업 여부를 확인하지 않은 “18영업일”로 바꾸어 부르지 않는다.

## 5. 공통 처리와 조회 — F01

사용자가 일간 날짜 또는 월간 연·월을 선택하면 해당 날짜 범위의 판매·비용을 집계한다. 첫 조회는 저장된 판매의 가장 최근 날짜가 속한 월로 한다. 판매가 없다면 한국 날짜 기준 현재 월을 선택한다.

기간·자료 범위·마감 여부를 함께 표시한다. 영업달력의 마감 완료 날짜는 확정, 마감 전 날짜는 미확정, 달력에 없는 날짜는 마감 정보 없음으로 구분한다. 2026-09-18 같은 샘플 날짜를 입력 가능 최종일로 고정하지 않는다.

**확정 실적**은 마감 완료 날짜만 집계한다. 미마감·마감 정보 없는 날짜에 직접 저장한 실제 판매·비용은 목록에 남기고 **입력 실적(미확정)**으로 별도 집계한다. 이는 예상값이 아니다. 해당 날짜의 실적이 아직 전부 입력되었다고 주장하지 않는다. 매장 손익도 같은 날짜 집합의 판매·비용·폐기를 사용하며 확정/미확정 값을 섞지 않는다. 1차에는 별도의 마감 처리 기능을 추가하지 않는다.

확정 날짜에 판매 기록이 없으면 “판매 기록 없음”을 표시한다. 존재하는 판매의 합계는 0으로 표시할 수 있으나 누락이 없다고 보증하지 않는다. 비용 없음 역시 “비용 기록 없음”과 합계 0을 함께 표시한다. 자료 시작 전 날짜는 자료 없음, 미래 미마감 날짜는 미확정으로 표시하며 확정 0으로 채우지 않는다.

재고 기준일은 일간은 선택일, 월간은 해당 월에서 판매·재고 기록이 존재하는 가장 최근 날짜로 한다. 기록 없는 월은 그 월 말까지 이어지는 계산 잔량이 가능하면 그 기준일과 “해당 월 활동 기록 없음”을 표시한다. 오늘 이후 날짜는 잔량 실적 조회 기준일로 사용하지 않는다. 초기재고 전 시점은 계산 불가다.

채널·메뉴·분류 필터는 해당 화면의 실적에만 적용하고 조건을 표시한다. 매장 전체 손익과 재료 잔량을 특정 메뉴 필터 결과로 오해하게 하지 않는다. 링크 이동 시 기간을 전달하며 재고는 별도 기준일을 명시한다. 조회로 기록·파일은 바뀌지 않는다.

오류: 잘못된 날짜·범위는 조회 중단과 항목 안내. 로딩 실패는 재시도 안내, 이전 결과가 남으면 이전 조건의 결과임을 표시. 비용·원가가 누락되면 관련 계산을 불완전으로 표시하고 0으로 대체하지 않는다.

## 6. 판매 관리 — F02~F04

### F02. 신규 판매와 미리보기

입력: 판매일, 원본 메뉴, 매장/포장, 판매수량, 판매단가, 기록 전체의 총 할인금액, 실제 결제수수료 금액. 시안에 없는 수수료 칸은 원본의 필수 계산 자료를 입력하기 위한 보완이며 새 분석 기능이 아니다. 비율 자동 적용은 하지 않는다. 실제 수수료가 0이면 사용자가 0을 입력하고, 모르면 빈칸을 0으로 보정하지 않고 저장을 중단한다.

기본값: 판매일은 조회 중인 유효한 과거·오늘 날짜를 사용하고 미래 월이면 오늘로 한다. 메뉴·채널은 선택 전 상태, 수량·수수료는 빈칸, 할인은 0이다. 메뉴 선택 시 원본 판매기준가와 레시피 버전을 연결하며 단가는 수정 가능하다. 원본에는 메뉴 판매가 이력이 없으므로 과거 판매가를 알고 있다고 가정하지 않는다.

수량·단가·할인·수수료·채널·메뉴·날짜 변경 → C01~C04 계산 → 순매출·식재료원가·포장원가·수수료·수익금액/비율·사용 재료·저장 후 예상 잔량 미리보기. 메뉴를 바꾸면 레시피도 바뀐다. +1/+5/+10은 현재 수량에 더하며 빈칸은 0에서 시작한다. 숫자가 아닌 값은 먼저 수정 안내한다. 할인은 사용 재료를 줄이지 않는다.

검증 후 저장하면 새 판매번호를 부여하고 목록·수익성·손익·재고를 일관되게 갱신한다. 미확정 날짜는 F01에 따라 분리한다. 미리보기는 저장 전 원장을 바꾸지 않으며, 성공은 실제 보관 성공 후 표시한다. 원본 엑셀·JSON은 덮어쓰지 않는다. 저장만으로 백업 파일을 만들지 않는다.

초기화는 위 기본값으로 되돌린다. 수정 중 초기화는 원래 저장값으로 되돌린다. 입력을 바꾼 상태에서 초기화·취소·닫기를 누르면 입력을 버릴지 확인한다. 취소하면 원장 변화 없음.

**입력 검사:** 필수값 누락, 잘못된 날짜·메뉴·채널, 숫자 아닌 값은 저장 중단. 수량은 양의 정수, 단가·할인·수수료는 0 이상이다. 할인은 정상 판매액 이하여야 한다. 무료 판매와 전액 할인은 허용하되 수익률은 계산 대상 없음으로 표시한다. 수수료가 매출을 넘더라도 실제 지출일 수 있어 확인 안내 후 음의 수익을 허용한다. 음수 판매를 환불로 자동 해석하지 않는다.

원본 시작일 전과 한국 날짜 기준 오늘 이후의 판매일은 실제 판매 저장을 막는다. 휴무일로 기록된 날짜는 불일치 안내 후 명시적으로 확인하면 실제 판매를 저장하며 영업달력을 자동 변경하지 않는다. 미마감 날짜와 달력에 없는 과거 날짜는 저장 가능하나 미확정으로 구분한다.

**중복:** 같은 날짜·메뉴·채널이 있으면 자동 합산하거나 신규 중복 생성하지 않고 기존 기록 수정으로 안내한다. 날짜·메뉴·채널을 바꾸는 수정도 같은 검사를 한다. 하루에 같은 메뉴의 판매단가가 여러 개라면 총 정상 판매액을 총수량으로 나눈 평균 단가로 한 기록에 입력하고, 프로그램이 산출한 정상 판매액을 확인한다. 개별 가격대·주문별 명세는 1차에서 관리하지 않는다.

**자료 부족:** 레시피·적용가격·구매용량이 없거나 잘못되면 새 판매 저장을 중단하고 해당 메뉴·재료·날짜를 안내한다. 기존 수입 자료의 누락은 원본을 보존하면서 관련 분석을 계산 불가로 표시한다. 원가율 25% 같은 값으로 대체하지 않는다.

**재고·실패:** 계산 잔량이 음수면 숨기지 않고 입고 누락·재고 확인 안내 후 사용자 확인으로 판매를 저장할 수 있다. 안전재고·부족 예측 기능은 아니다. 저장 실패 시 입력과 기존 원장을 유지한다. 저장 중 재클릭·재시도는 같은 요청을 중복 생성하지 않는다.

### F03. 판매 조회·필터·페이지

기간·채널·메뉴에 맞는 일자·메뉴·구분·채널·수량·단가·총 할인·순매출·수수료·식재료원가·포장원가와 마감 상태를 표시한다. 음료는 잔, 디저트는 개로 구분하고 합계는 판매수량으로 부른다. 할인 입력은 양의 차감액, 표시는 차감액임을 명시한다.

날짜 최신순, 같은 날짜는 메뉴번호·채널·판매번호 순으로 고정한다. 페이지당 8건, 필터 변경 시 첫 페이지로 이동한다. 필터 초기화는 F01의 첫 조회 월·전체 채널·전체 메뉴·첫 페이지로 되돌린다. 전체 필터 합계와 현재 페이지 합계는 별도 표시하고 미확정 합계도 분리한다. 페이지 수는 조회 건수÷8 올림이며 6,112건 전체는 764페이지다. 결과 없음은 0건과 빈 목록으로 표시하고 존재하지 않는 페이지 이동은 막는다. 마지막 행 삭제로 페이지가 사라지면 직전 유효 페이지로 이동한다. 조회로 파일을 만들지 않는다.

### F04. 판매 수정·삭제

수정 버튼 → 기존 값·당시 레시피/원가/수수료 표시 → 변경 미리보기 → 저장.

수량·단가·할인만 수정하면 기존 개당 원가와 레시피 버전을 유지하고 금액을 재계산한다. 수수료는 새 금액을 사용자가 확인해 저장하며 자동 비례 조정하지 않는다. 날짜·메뉴·채널을 바꾸면 해당 날짜의 가격이력·해당 메뉴 레시피·채널로 원가와 사용량을 다시 산정하고 변경 근거를 표시한다. 재료가격 변경만으로 기존 판매 원가를 일괄 바꾸지 않는다. 원본의 기존 순매출은 수정 전 보존하고, 수정 저장 시 C01 기준으로 다시 산정한다.

변경 전 영향은 제거하고 변경 후 영향을 반영한다. 날짜 변경은 양쪽 기간을 갱신한다. 재고를 새 수량만큼 추가 차감하지 않고 F07 기준으로 다시 산출한다.

삭제는 날짜·메뉴·채널·수량을 보여 준 뒤 확인받고 제외한다. 취소는 변화 없음. 실사 전 판매 수정·삭제의 현재 재고 영향은 F07에 따른다. 대상이 이미 없거나 편집 중 달라졌으면 재조회 안내. 검증·저장·삭제 실패 시 기존 기록 유지, 수정 입력 보존. 파일 생성 없음.

## 7. 메뉴 수익성 — F05

일·월과 전체/음료/디저트 분류를 선택하면 메뉴별 판매수량·순매출·식재료원가·포장원가·수수료·수익금액·수익률을 표시한다. 확정/미확정 실적은 F01 기준으로 분리한다.

메뉴 수익은 순매출에서 식재료·포장재·결제수수료를 뺀 금액이다. 이를 공헌이익이라 부르며, 임대료·인건비와 폐기 손실을 반영한 매장 손익과 구분한다. 전체 수익률은 총수익÷총순매출로 구하고 개별 수익률을 단순 평균하지 않는다. 채널 비중은 판매수량 기준이다.

단가가 여러 개인 조회 기간에는 “평균 판매단가”라고 표시한다. 평균은 총 정상 판매액÷총수량이며 할인 후 개당 매출과 구분한다. 행별 원가 분석은 해당 메뉴 기록의 당시 원가·레시피·가격 근거 조회로 제한하며 수정 기능을 실행하지 않는다.

판매 없음은 수량 0·실적 없음, 매출 0의 수익률은 계산 대상 없음으로 표시한다. 원가 누락 시 해당 메뉴·전체의 불완전 상태를 표시하고 누락분을 0으로 더하지 않는다. 같은 범위 판매표와 메뉴표 합계를 대조하고, 다르면 원장 일치 표시를 하지 않는다. Star·4분면·최우수 등 평가는 2차다. 파일 생성 없음.

## 8. 기간 실적·매장 손익 — F06

일·월 선택 → 동일 마감 범위의 전체 판매·귀속일 비용·폐기 집계 → 순매출·식재료·포장·결제수수료·운영비·폐기 손실·매장 손익 표시. 확정과 미확정의 계산 범위는 F01에 따른다.

실제 비용은 일별 비용기록으로 집계한다. 월계획은 참고값이며 다시 더하거나 일별 비용을 새로 만들어 중복 반영하지 않는다. 사용자가 새 비용에 지정한 귀속일은 그 비용을 어느 날짜의 실적으로 볼지 뜻한다. 지출일과 같을 필요는 없다.

명시적으로 기록한 폐기는 폐기일 적용가격에 따른 재료 원가로 평가하고 메뉴 수익에서 빼지 않고 매장 손익에서 따로 한 번 반영한다. 재료 입고 대금을 판매 원가와 다시 더하지 않는다. 실사 차이는 원인 미확정 수량 조정으로만 취급하며 자동으로 폐기 비용을 만들지 않는다.

이 손익은 기록된 판매·운영비·명시적 폐기를 이용한 관리용 손익이다. 세금·감가상각·모든 재고평가 차이까지 반영한 회계 결산이라고 표시하지 않는다. 계산 근거가 부족한 폐기는 손익 불완전으로 표시한다.

순매출 0이면 손익 금액은 표시하되 손익률은 계산 대상 없음. 판매 없이 비용이 있으면 손실을 표시한다. 메뉴 수익 합계에서 운영비·폐기 손실을 뺀 값이 매장 손익과 일치해야 한다. 객단가·주문 수·손익분기점·목표 대비 평가는 1차에 추가하지 않는다. 파일 생성 없음.

## 9. 재고 기록·잔량 — F07

전용 시안은 없으므로 재료별 기준일 잔량과 다음 기록 입력을 화면 설계에서 보완한다.

| 행동 | 입력 | 처리·화면 결과 |
| --- | --- | --- |
| 잔량 조회 | 기준일, 재료 | 초기재고·저장 판매·입고·폐기·실사를 연결한 잔량·단위·기준일 표시 |
| 입고 저장 | 날짜, 재료, 양의 수량, 공급사·사유(선택), 입고 단위원가(선택) | 입고량 증가, 판매·매출 변화 없음. 원가는 선택값이며 날짜별 가격이력을 자동 변경하지 않음 |
| 폐기 저장 | 날짜, 재료, 양의 폐기량, 사유 | 감소 처리. 폐기일 가격이력으로 손실 평가해 매장 손익에 한 번 반영 |
| 실제 재고 저장 | 날짜, 재료, 직접 센 0 이상 수량 | 해당 날짜 마감 시점의 실측값을 새 기준으로 사용. 차이는 조정량으로 설명 |

단위는 재료의 원본 단위를 자동 표시하고 변경 입력을 받지 않는다. g·ml은 소수 최대 3자리, 개는 정수 입력이다. 원본 수량은 원래 정밀도로 보존한다. 입고·폐기 0은 기록하지 않고, 실제 재고 0은 유효하다. 사유가 없는 폐기는 입력 안내 후 보완하도록 한다.

날짜만 있는 자료는 하루의 초기 잔량 → 입고 → 판매 사용량·폐기 → 마감 실사 순서로 해석한다. 같은 재료·날짜의 실측 입력은 하나만 허용한다. 같은 날 다시 실측을 저장하려 하면 중복 안내로 중단한다. 1차에 재고 기록 수정·삭제 기능을 추가하지 않는다.

**실사 기준:** 실측수량이 있는 기록은 그날 마감 잔량을 해당 실측값으로 맞춘다. 함께 기록된 조정량을 또 더하지 않는다. 실측수량 없이 조정량만 있는 기존 기록은 증감량을 적용한다. 더 늦은 실사가 있다면 이전 판매 수정은 당시 계산 잔량·실사차이를 바꾸지만 이후 실측값을 넘어 현재 잔량을 소급 변경하지 않는다. 마지막 실사 이후 판매 수정은 현재 잔량에도 반영한다.

재고는 저장된 실제 판매를 기준으로 산출하며 미확정 판매도 차감한다. 해당 잔량에 미확정 입력이 포함되면 표시한다. 실적의 마감 포함 여부 때문에 이미 판매한 재료가 재고에 남은 것처럼 되돌리지 않는다. 미래 미저장 판매·예측은 차감하지 않는다. 포장 전용 재료는 포장 판매에만 적용한다.

**예외:** 날짜·재료·수량 오류, 알 수 없는 공급사, 단위 불일치, 음수 실측, 시작 전·미래 날짜는 중단. 폐기 손실의 가격 근거가 없으면 폐기 저장을 중단한다. 입고 기록 자체는 가격이 선택값이므로 잔량을 기록할 수 있으나 판매 원가용 가격이력을 대체하지 않는다. 예상 잔량 음수는 숨기지 않고 확인 후 입고·폐기·판매 기록 저장을 허용한다. 시작 재고가 없거나 과거 판매 사용량을 알 수 없으면 해당 재료 잔량을 계산 불가로 표시한다. 실측값 이후는 그 값을 기준으로 다시 계산할 수 있다.

성공 후 재고 목록·잔량·관련 수익성/손익 근거 갱신. 실패 시 입력 유지·기존 기록 보존. 백업 자동 생성 없음. 안전재고 경고·발주량은 2차다.

## 10. 비용 관리 — F08

전용 시안은 없다. 귀속일·원본 8개 비용항목 중 하나·금액을 입력하고 기록별 등록·수정·삭제를 제공한다. 새 비용 출처는 직접 입력으로 구분하고 기존 배분기준은 보존한다.

저장 시 해당 기간 비용·손익 갱신. 수정은 기존 금액을 교체하고 날짜 변경은 양쪽 기간 반영. 삭제는 날짜·항목·금액 확인 후 제외하며 취소 시 변화 없음. 기간·항목 필터별 목록과 합계를 표시한다. 비용 편집은 판매량·재료 잔량을 바꾸지 않는다.

금액은 양의 정수 원 단위이며 0원은 비용 없음과 구분하기 어려워 새 비용 기록으로 저장하지 않는다. 음수 비용을 환급으로 자동 처리하지 않는다. 빈칸·숫자 오류·미등록 항목·시작 전 귀속일은 중단한다. 오늘 이후 귀속 비용은 실제 비용이 아닌 계획에 해당하므로 1차 직접 입력에서는 막고 2차 비용계획으로 안내한다.

월비용 전체를 한 날짜에 입력하면 그 귀속일에 전액 반영하고 자동 일할 배분하지 않는다. 저장 전 영향을 안내한다. 같은 날 같은 항목의 여러 지출은 허용하되 완전히 동일한 날짜·항목·금액의 재입력은 중복 가능성을 확인받는다. 이미 배분된 임대료 등을 또 넣지 않도록 기존 비용을 표시한다. 자동으로 같은 지출이라고 단정해 삭제하지 않는다.

입고 대금·자동 평가 폐기 손실을 운영비에 다시 입력하지 않도록 안내한다. 현재 8개 운영비 항목에 재료 구매·폐기 항목을 새로 추가하지 않는다. 실패 시 기존 기록과 입력 유지. 파일 생성 없음.

## 11. 저장·백업·복원 — F09~F10

### F09. 기록 저장과 다시 열기

각 기록 저장 성공 시 판매·비용·재고와 연결 정보를 보관한다. 다시 열면 마지막 성공 기록을 불러온다. 별도의 전체 저장 버튼은 두지 않는다. 성공/실패·최근 저장 시각을 알리고 미리보기·미저장 초안은 저장된 자료와 구분한다.

저장 불가·공간 부족·읽기 실패는 재시도 안내. 실패를 성공으로 표시하거나 기본 샘플로 자동 덮어쓰지 않는다. 관련 원장 일부만 반영하지 않으며 재시도도 중복 생성하지 않는다. 초기 샘플은 저장된 운영 기록이 없는 최초 사용에만 적용한다. 초기자료에 오류가 있으면 해당 오류를 알려 주고 잘못된 완전 성공을 표시하지 않는다.

다른 기기 자동 공유·로그인·클라우드 동기화는 추가하지 않는다. 구체 저장 기술·배포 환경은 개발 설계에서 선택하되 위 동작과 백업 기능을 충족해야 한다.

### F10. 전체 백업과 복원

백업 버튼 → 저장된 전체 운영 기록·기초 정보·영업달력·제품 설정 수집 → 복원 가능한 JSON 파일 내려받기. 출처·자료기간·백업일시·형식 버전과 모든 기록번호 연결을 포함한다. 예시 파일명은 `프렙카페_전체백업_YYYYMMDD_HHMMSS.json`이다. 백업일시 표시는 한국 시간 기준으로 한다. 미저장 초안은 포함하지 않는다고 안내한다. 금액·수량·빈칸·0의 구분과 원본 정밀도를 보존한다.

복원 버튼 → 파일 선택 → 형식·버전·필수 정보·중복 번호·참조·단위·수치 검사 → 현재/복원 기록 수·기간과 전체 대체 안내 → 사용자 확인 → 전체 반영·재집계. 자동 병합하지 않는다. 복원 전 현재 기록의 백업을 권유하고 사용자가 취소할 수 있게 한다.

손상·미지원 버전·끊어진 참조·중복 집계키·수치 오류는 반영 전 중단하고 이유 표시. 일부 데이터만 복원하지 않는다. 0바이트 파일·필수 구조 없는 파일은 거부한다. 구조가 정상이고 메뉴·재료 등 필수 기초 정보가 유효하다면 판매·비용·재고 활동 기록 0건은 허용하며 “활동 기록 없음으로 전체 대체”를 명확히 확인한다. 원본 운영 JSON은 제품 백업과 형식이 다를 수 있어 자동 복원 파일로 취급하지 않는다.

파일 선택·확인 취소, 검사·반영 실패는 기존 전체 기록 유지. 내려받기 시작과 사용자 기기의 파일 저장 완료는 구분한다. 보관 성공 후에만 복원 완료 표시. 분석용 엑셀·PDF 파일은 생성하지 않는다.

## 12. 계산 기준

모든 화면은 같은 기록 범위·계산·반올림 기준을 사용한다. 기존 원본 당시 값은 그대로 보존하며 수정한 판매에만 F04 정책을 적용한다.

| 번호 | 계산 | 기준·예외 |
| --- | --- | --- |
| C01 | 정상 판매액 = 수량×판매단가. 순매출 = 정상 판매액−총 할인 | 정상 판매액은 기록 단위 정수 원으로 반올림. 할인은 기록 전체의 정수 원 금액. 초과 할인 중단 |
| C02 | 재료 단위 가격 = 적용 구매가격÷구매용량. 개당 원가 = 적용 레시피 사용량×단위 가격의 합 | 판매일 이하 가장 최근 가격이력 사용. 구매용량 0·누락은 계산 불가. 채널 조건 적용 |
| C03 | 식재료원가 = 수량×개당 식재료원가. 포장원가 = 수량×개당 포장원가 | 기존은 당시 원가, 신규는 C02. 식재료와 포장 재료는 원본 연결 기준으로 구분. 각각 기록 단위 정수 원 반올림 |
| C04 | 메뉴 수익 = 순매출−식재료원가−포장원가−실제 결제수수료. 수익률 = 수익÷순매출×100 | 매출 0이면 비율 계산 불가. 수수료 2.5% 자동 적용 없음 |
| C05 | 실적 합계 = 해당 범위 기록 금액·수량의 합. 전체 수익률 = 총수익÷총순매출×100 | 개별 비율의 단순 평균 사용 안 함. 확정/미확정·기간·필터 일치 |
| C06 | 매장 손익 = 전체 메뉴 수익−귀속 운영비−명시적 폐기 손실. 손익률 = 손익÷총순매출×100 | 폐기 손실은 폐기량×폐기일 단위 가격으로 기록별 반올림. 월계획·입고대금·폐기를 중복 비용 처리하지 않음 |
| C07 | 실사 없는 구간: 시작 잔량+입고−폐기−판매 재료 사용량+실측값 없는 조정량. 실측값 있는 시점: 잔량을 실측값으로 교체 | 판매 사용량 = 레시피 사용량×수량. 실사 후부터 다시 증감 계산. 실측과 조정 이중 반영 금지 |
| C08 | 채널 비중 = 채널 수량÷총수량×100. 페이지 수 = 조회 건수÷8 올림 | 수량 0은 비율 계산 불가. 빈 목록은 페이지 이동 없음 |
| C09 | 평균 판매단가 = 총 정상 판매액÷총수량 | 평균임을 명시. 할인 후 개당 매출·주문당 객단가와 구분 |

단가·원가의 중간 계산은 정수로 잘라 버리지 않는다. 기존 원본의 소수 원가는 그대로 보존한다. 새 금액은 C01/C03/C06에서 정한 기록 단위로 반올림하고, 화면 합계는 해당 정수 기록 금액의 합으로 표시해 메뉴표·손익표 합계가 같게 한다. 음수 손익·재고는 0으로 보정하지 않는다. 비율은 소수 첫째 자리, g·ml 잔량은 소수 셋째 자리까지, 개는 정수로 표시한다. 백업은 표시용 문자열 대신 수치 자체를 보존한다.

판매수량은 양의 정수이며 시안의 999 상한을 적용하지 않는다. 판매단가는 평균 단가 입력을 위해 소수를 허용하고, 할인·수수료·새 운영비는 정수 원 단위로 받는다. 숫자가 너무 크거나 정밀하게 처리할 수 없으면 잘라 저장하지 않고 범위 오류로 안내한다.

**자료 기반 사용량 예:** 카페라떼 20잔은 원두 400g·우유 4,000ml를 사용한다. 포장 판매라면 포장컵세트 20개를 추가 사용한다. 할인 여부와 무관하다.

**설명용 금액 예:** 수량 20, 단가 5,000원, 할인 2,000원이면 순매출은 98,000원이다. 식재료 20,000원·포장 3,000원·실제 수수료 1,500원이면 메뉴 수익 73,500원·수익률 75.0%다. 같은 범위 운영비 30,000원·폐기 손실 2,000원이면 매장 손익 41,500원이다. 이 숫자는 원본 집계 결과가 아니다.

| 미마감 판매와 잔량 | 실적은 분리·재고는 실제 저장 판매 차감, 0원 확정 처리 없음 |
| 페이지·필터·원장 대조 | 페이지 합계/전체 합계 분리, 동일 조건 메뉴·판매·손익 연결 |
| 저장 실패·중복 클릭·재시도 | 입력·기존 원장 보존, 부분 저장·중복 생성 없음 |
| 정상 백업 복원·손상·취소·정상 0건 | 정상은 기록 연결·계산 재현, 손상/취소는 유지, 0건 대체는 명시적 확인 |

PRD 연결: M1→F02~F04, M2→F08, M3→F05, M4→F01/F06, M5→F07, M6→F09/F10. 시안 없는 필수 기능도 포함했다. 승인되지 않은 버튼·기능은 실행 대상에 추가하지 않았다. 1차의 완료 판정은 이 표의 동작과 PRD의 4시간 범위에 맞춰 한다.

## 15. 결정 요약과 후속 범위

| 항목 | 이번 문서의 기준 |
| --- | --- |
| 시안과 범위 | PRD 우선, 1차·2차 구분 유지. 추가 연동·출력·실제 주문 전송 제외 |
| 메뉴/매장 수익 | 메뉴는 직접비·수수료, 매장은 운영비·명시적 폐기 손실 추가 반영 |
| 신규 수수료 | 실제 금액 입력. 미확인 비율 자동 채택 없음 |
| 기존 판매 수정 | 당시 근거 보존, 날짜·메뉴·채널 변경 시 해당 기준 재적용 |
| 미마감 | 입력 허용·실적 분리·재고는 실제 기록 반영. 1차 마감 기능 추가 없음 |
| 재고·실사 | 마감 실측값 기준, 음수 숨김 없이 확인 후 기록 |
| 비용 | 귀속일 집계·월계획 참고·새 0원 비용 제외 |
| 저장/백업/복원 | 기록별 저장·전체 JSON 백업·검사 후 확인받아 전체 대체 |
| 입력·표시 | F02/F03/C01~C09 기준. 고정 샘플 초기값·999 상한 적용 안 함 |

1차 기능에 대한 추가 선택 질문은 없다. 전용 시안 없는 화면의 배치, 저장 기술·배포 환경은 후속 설계에서 이 명세를 충족하도록 정한다. 2차의 상세 예측·발주·분류·가져오기 정책은 13절 참고안을 바탕으로 2차 착수 시 결정한다. 이를 1차 미완료 기능으로 보거나 자동으로 1차에 추가하지 않는다.
