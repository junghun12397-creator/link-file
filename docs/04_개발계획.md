# 프렙 카페 개발계획

상태: 직전 대화에서 제안한 개발계획을 이번 EPIC 구현 요청의 기준으로 기록함.  
근거: 01_PRD.md, 02_FRD.md, 03_TRD.md, design/_1~_4 및 artisan_ops/DESIGN.md.  
완료 원칙: 자동 검사 통과와 사용자 화면 확인을 구분한다. 사용자가 문제없이 확인한 EPIC만 완료로 표시한다.

## 전체 작업 순서와 개수

판매 입력·메뉴 수익성 → 비용·매장 손익·재료 잔량 → 재고 기록·백업·복원 순서다.

EPIC은 작업 묶음, User Story는 사용자가 한 가지 목적을 달성하는 기능이다. 총 EPIC 3개·Story 15개이며 각 EPIC은 5개 Story다. 수정·삭제, 입고·폐기·실사를 개별 확인하기 위해 분리했다. 개수를 줄이기 위해 별개 목적을 하나로 합치지 않았다.

| 순서 | EPIC | Story | 상태 |
| --- | --- | --- | --- |
| 1 | 판매 기록과 메뉴 수익성 | S01~S05 | 완료 — 2026-10-12 사용자 일괄 확인 |
| 2 | 비용과 매장 실적·잔량 | S06~S10 | 완료 — 2026-10-12 사용자 확인 |
| 3 | 재고 기록과 자료 보관 | S11~S15 | 구현·검사 진행 중 — 미완료 |

판매는 수익성과 재료 사용량의 출발점이다. 이를 먼저 만든 뒤 비용을 연결해 매장 손익을 완성하고, 새 재고 기록과 전체 복구를 연결한다. 공통 계산·저장은 첫 Story부터 함께 구현하며 화면만 만들고 완료 처리하지 않는다. EPIC 2까지 기존 재고 자료를 사용하고 새 재고 입력은 EPIC 3에서 연결한다.

## 공통 완료 조건

- PRD 범위, FRD F01~F10·C01~C09, TRD의 저장·검사 원칙을 유지한다. 각 기능의 계산 정확성·실제 저장·기본 오류 처리는 해당 Story에 포함한다.
- 저장 성공 후만 성공 안내. 다시 열어도 유지. 실패는 기존 전체 자료·초안 유지. 중복 클릭·재시도는 한 번만 반영. 다른 탭의 오래된 수정으로 덮어쓰지 않는다.
- 확정·미확정, 없음·0·계산 불가를 구분한다. 음수 손익·재고는 숨기지 않는다. 예상치는 실제 기록에 섞지 않는다.
- 자동 검사는 가상 자료와 별도 기대값을 사용한다. 화면 확인은 검사 자료에서 수행하며 실제 운영자료를 지우지 않는다.
- 사용자가 Story별 화면 확인을 완료하고 발견 문제를 해결한 뒤에만 해당 EPIC을 완료로 표시한다. 부분 통과로 전체 EPIC을 완료 처리하지 않는다.

## EPIC 1 — 판매 기록과 메뉴 수익성

의존성: S01 조회·저장 기반 → S02~S04 등록·수정·삭제 → S05 같은 원장 수익성. 미리보기의 재료 사용량·잔량 계산은 여기서 포함한다. 독립 재고 화면과 입력은 다음 EPIC이다.

### S01. 기존 판매 기록을 찾아보기

- 할 수 있는 일: 일·월, 메뉴, 매장/포장 필터와 페이지 이동으로 기존 기록 조회.
- 자동 검사: 초기 자료 1회 반영, 최신 판매 월 기본값, 정렬·필터·8건 페이지·전체/페이지 합계, 미마감 구분, 저장된 활동 0건 자료 재초기화 방지.
- 화면 확인: 2026년 9월에서 메뉴·채널을 변경하면 일치하는 목록·합계가 나온다. 페이지 합계는 전체 합계와 구분되고 미마감 날짜를 확정 0으로 표시하지 않는다.

### S02. 새 판매를 입력하기

- 할 수 있는 일: 날짜·메뉴·채널·수량·단가·총 할인·실제 수수료를 입력해 미리보기 후 저장.
- 자동 검사: 날짜별 원가·레시피·포장·반올림·사용량, 필수값·날짜·중복·할인·가격 누락, 무료 판매·수수료 0·음수 잔량 확인, 중복 요청.
- 화면 확인: 유효한 비중복 날짜의 포장 라떼 20잔에서 원두 400g·우유 4,000ml·컵세트 20개 사용을 확인. 취소는 변화 없고 저장은 한 건만 남으며 재실행에도 유지.

### S03. 잘못 입력한 판매를 수정하기

- 할 수 있는 일: 기존 판매의 수량·금액·날짜·메뉴·채널 수정.
- 자동 검사: 수량·금액 수정은 당시 원가·레시피 유지. 날짜·메뉴·채널 변경은 재산정. 수수료 자동 비례 변경 금지, 이전 영향 제거, 중복 검사·실패 원상 유지.
- 화면 확인: 20잔→25잔 수정 시 한 기록만 남고 관련 실적·사용량이 갱신된다. 날짜 이동은 이전 날짜에서 빠지고 새 날짜에 반영된다.

### S04. 잘못 등록한 판매를 삭제하기

- 할 수 있는 일: 대상 날짜·메뉴·채널·수량 확인 후 삭제.
- 자동 검사: 확인·취소·대상 제거·합계·페이지 보정·실패 보존, 실사 전후 재고 영향.
- 화면 확인: 취소는 변화 없음. 확인은 해당 한 건과 관련 수익·사용 영향 제거. 새로고침 후에도 유지.

### S05. 메뉴별로 남는 금액과 근거 확인하기

- 할 수 있는 일: 일·월·분류별 실적·수익과 당시 원가·레시피·가격 근거 조회.
- 자동 검사: 직접비·수수료 차감, 합계 기준 수익률·평균 단가·수량 채널 비중, 원가 누락·0매출·판매표 합계 일치.
- 화면 확인: 동일 조건의 판매표와 메뉴표 합계 일치. 별도 검사 예시 순매출 98,000·식재료 20,000·포장 3,000·수수료 1,500원에서 수익 73,500원·75.0%. 원가 조회는 가능하나 편집은 없음.

완료 기준: S01~S05의 실제 계산·저장·오류 처리와 사용자 확인이 모두 통과. 고정 원가율·가짜 저장·가짜 동기화 없음.

## EPIC 2 — 비용과 매장 실적·잔량

의존성: EPIC 1의 기록·계산·저장 기반. S06~S08 비용을 S09에 연결. S10은 저장 판매·기존 입고·폐기·실사 활용.

### S06. 비용을 기록하고 찾아보기

- 할 수 있는 일: 귀속일·8개 항목·금액 입력, 기간·항목별 목록·합계 조회.
- 자동 검사: 유효 날짜·항목·양의 정수, 동일 재입력 확인, 월계획 중복·자동 일할 배분 금지.
- 화면 확인: 광고비 10,000원 추가 시 해당 귀속일 비용만 10,000원 증가. 판매량·잔량 불변. 동일 재입력은 확인.

### S07. 비용의 날짜·항목·금액 수정하기

- 할 수 있는 일: 기존 비용 수정.
- 자동 검사: 금액 교체·날짜 양쪽 반영·기존 배분기준 보존·실패 원상 유지.
- 화면 확인: 10,000→15,000원 수정은 25,000원이 아닌 15,000원. 날짜 이동은 이전 기간에서 빠지고 새 기간 반영.

### S08. 잘못 등록한 비용 삭제하기

- 할 수 있는 일: 날짜·항목·금액 확인 후 비용 한 건 제거.
- 자동 검사: 확인·취소·정확한 대상·비용 합계·실패 보존·판매/재고 불변.
- 화면 확인: 취소는 유지, 삭제는 해당 비용 제거. S09 연결 후 해당 금액만큼 손익 개선.

### S09. 일·월 실적과 매장 손익 확인하기

- 할 수 있는 일: 같은 기간 매출·원가·수수료·운영비·폐기·손익 조회, 수익성·재고 이동.
- 자동 검사: 동일 날짜 집합·확정/미확정 분리, 월계획·입고대금·폐기 중복 금지, 실사 차이 자동 비용 금지, 0매출·누락 상태.
- 화면 확인: 수익 73,500−운영비 30,000−폐기 2,000=손익 41,500원(검사 예시). 비용만 있으면 손실. 불완전 근거는 불완전 표시.

### S10. 기준일의 재료 잔량 확인하기

- 할 수 있는 일: 기준일·재료별 잔량·단위·미확정 입력 포함 여부 조회.
- 자동 검사: 초기→입고→판매/폐기→마감 실사, 포장 전용·실측 이중 반영 방지·실사 전후 수정/삭제·기록 없는 월·시작 전/미래 기준일.
- 화면 확인: 이후 실사 없는 검사 구간의 라떼 20잔 저장으로 우유 4,000ml 감소. 미확정 판매도 차감. 실적 기간과 재고 기준일 구분.

완료 기준: 비용 관리와 판매→메뉴 수익성→동일 기간 손익→재료 잔량의 실제 화면 흐름이 사용자 확인까지 통과.

## EPIC 3 — 재고 기록과 자료 보관

의존성: EPIC 2 잔량·손익에 새 기록 연결. 전체 기록 구조가 연결된 뒤 백업·복원 검증.

### S11. 재료 입고 기록하기

- 할 수 있는 일: 날짜·재료·입고량 입력. 공급사·사유·단위원가 선택 입력.
- 자동 검사: 단위·양수·g/ml 소수 3자리·개 정수·날짜/공급사, 가격이력 자동 변경·중복 비용 금지.
- 화면 확인: 이후 실사 없는 구간 우유 1,000ml 입고로 잔량만 1,000ml 증가. 재실행에도 유지.

### S12. 재료 폐기 기록하기

- 할 수 있는 일: 날짜·재료·폐기량·사유 입력.
- 자동 검사: 사유·수량·날짜·가격 근거·반올림·손실 1회·음수 확인·실패 전체 미반영.
- 화면 확인: 단가 2원/ml 검사 자료의 100ml 폐기는 잔량 −100ml, 매장 손익 −200원. 메뉴 수익 불변.

### S13. 직접 센 실제 재고 기록하기

- 할 수 있는 일: 날짜·재료별 실측값을 마감 잔량 기준으로 기록.
- 자동 검사: 0 허용·음수/같은 날 재료 중복 금지·실측 기준 교체·조정량 이중 반영 방지·이전/이후 판매 수정.
- 화면 확인: 계산 900ml에 실측 800ml 입력하면 잔량 800ml·차이 −100ml. 자동 폐기 비용 없음. 이전 판매 수정에도 실측 기준 유지.

### S14. 전체 자료를 백업 파일로 보관하기

- 할 수 있는 일: 저장된 전체 운영·기초 자료를 JSON 다운로드.
- 자동 검사: 전체 기록·설정·달력·연결·버전·소수/null/0 보존, 초안 제외·실제 파일 생성.
- 화면 확인: 한국 시간 파일명과 다운로드 시작 안내. 초안 미포함. 기기 저장 완료를 확인했다고 허위 표시하지 않음.

### S15. 백업 파일로 전체 자료 복원하기

- 할 수 있는 일: 파일의 건수·기간·전체 대체 확인 후 복원.
- 자동 검사: 구조·버전·참조·중복·단위·수치, 전체 결과 재현·취소/손상/실패 원본 보존·정상 활동 0건·다른 탭 충돌.
- 화면 확인: 백업 이후 추가한 검사 판매가 복원 후 사라지고 백업 당시 수익·손익·잔량 재현. 손상·취소는 변화 없음.

완료 기준: 모든 재고 입력이 잔량·손익에 정확히 연결되고 실제 다운로드 파일 복원으로 전체 상태를 재현. 실패 시 부분 반영 없음. 사용자 확인 필요.

## 최종 검사·배포·시간

자동 검사와 배포는 Story 수에 포함하지 않지만 필수 작업이다. 각 EPIC 검사에 더해 최종 핵심 흐름·TRD 성능 목표·키보드·좁은 화면·개인정보 전송 여부를 확인한다. GitHub에서 실제 자료·백업·비밀정보 제외를 점검하고 Vercel 운영 주소에서 새로고침·저장·파일 흐름을 다시 검사한다. Preview와 운영 주소 자료는 분리된다.

기획 30분·설계 20분·개발 115분·검사 45분·배포 30분, 총 240분 목표를 유지한다. 이전 문서 작성 포함이며 매 EPIC마다 새 4시간이 아니다. 목표 초과 시 필수 검사나 기능을 임의 제거하지 않고 재협의한다.
