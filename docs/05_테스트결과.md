EPIC 3: 기능 구현 및 계산·저장 115개 검사 통과 — **사용자 확인 전 미완료**. 최종 화면·속도 결과는 마지막 절 참조. GitHub 업로드: 계정 인증 취소로 미전송, 로컬 Git 보관. Vercel 배포: 수행하지 않음.

docs/04_개발계획.md가 없었으므로 직전 대화의 3개 EPIC·15개 Story 계획을 기록하고 첫 EPIC을 대상으로 삼았다. 자동 검사 결과와 사용자가 직접 확인한 결과를 분리한다. 사용자 확인을 대신 통과 처리하지 않는다. 문제 보고 시 수정·재검사 후 같은 확인 단계부터 다시 진행한다.

## 검사 환경·실행

- Windows, Node v24.19.0, npm 11.17.0. TRD의 22.12 이상 조건을 충족하는 설치된 환경으로 검사. 향후 배포 시 Node 버전 일치 확인 필요.
- React·TypeScript·Vite, IndexedDB/Dexie, decimal.js, lossless-json, Zod. 설치 결과는 package-lock.json으로 고정.
- 실제 화면 검사는 설치된 Microsoft Edge의 검사 전용 새 브라우저 프로필에서 Playwright로 수행. 사용자 프로필·자료는 삭제하지 않음.
- 로컬 주소: http://127.0.0.1:5173/#/sales (사용자와 서버가 같은 PC). 같은 주소·브라우저·프로필에서 자료 유지.
- 자동 확인 명령: npm run typecheck / npm run test -- --run / npm run test:e2e / npm run build.
- 원본 엑셀·JSON은 읽기 전용이며 변경하지 않음. 초기 입력은 가상 원본 JSON 한 형식만 사용.

## 완료 판정과 제한

- EPIC 1은 사용자의 위 일괄 확인에 따라 완료. EPIC 2는 자동 검사와 별도로 사용자가 문제없이 확인한 뒤에만 완료로 표시한다.
- 이 절은 EPIC 2 검사 당시 기록이다. 당시 EPIC 3은 미착수였으며, 이후 구현·검사 현황은 문서 마지막 EPIC 3 절을 따른다.
- 백업이 아직 없으므로 실제 운영 시작용이 아니라 가상 자료 검사용이다. 브라우저 자료 삭제·기기 고장 복구를 보장하지 않는다.
- 로컬 결과이며 Vercel 운영 배포·배포 보안 헤더 검증·도메인 이동 검사는 아직 수행하지 않았다.
- 자동 검사의 실제 오류 주입·다중 탭 검사는 사용자가 눈으로 확인한 결과로 대체 기록하지 않는다.

## EPIC 2 — 구현·검사 기록

범위: S06 비용 등록·조회, S07 비용 수정, S08 비용 삭제, S09 일·월 매장 손익, S10 재료 잔량 조회. 재고 입력·백업·복원은 구현하지 않았다. 같은 DB 이름·형식 버전을 유지해 기존 EPIC 1의 사용자 기록을 지우거나 다시 초기화하지 않는다. 새로운 의존 라이브러리·외부 서비스는 추가하지 않았다.

Sites 지침의 로컬 미리보기 절차를 적용했다. 기존 개발 서버·주소를 재사용하고 로컬에서 검사한다. 호스팅 등록·외부 배포는 하지 않는다. 시안의 따뜻한 색과 표·입력창을 재사용하며, 시안의 가짜 수수료율·예측·발주·동기화는 도입하지 않았다. 전용 시안이 없는 비용·잔량은 같은 화면 규칙으로 보완했다.

### 검산 기준

운영비와 폐기 손실은 앱 계산 함수를 호출하지 않고 원본 JSON을 PowerShell의 decimal로 별도 합산했다. 폐기는 음수 수량의 절댓값에 폐기일 이하 최신 구매가격/구매용량을 적용하고, 기록별 원 단위 반올림 후 합산했다.

| 원본 2026년 9월, 전체 매장 확정 | 기대값 |
| --- | ---: |
| 메뉴 수익 | 10,212,729원 |
| 귀속 운영비 (144건) | 3,798,010원 |
| 명시적 폐기 손실 (9건) | 21,534원 |
| 매장 손익 | 6,393,185원 |
| 손익률 | 45.8% |
| 월비용계획 (참고만, 합산 안 함) | 6,330,000원 |

별도 검사 자료에서는 FRD 예시 73,500−30,000−2,000=41,500원을 확인했다. 판매 없이 광고비만 10,000원 입력한 날은 손익 −10,000원, 손익률 계산 대상 없음이다.

원본 이후 2026-09-19 포장 라떼 20잔을 입력한 별도 브라우저 검사는 메뉴 수익·매장 손익 70,708원, 광고비 10,000원 추가 후 매장 손익 60,708원이다. 우유는 23,180→19,180ml, 원두는 4,280→3,880g, 컵세트는 214→194개. 운영비 추가 전후 잔량은 불변이며 미확정 판매 사용량은 실제로 차감한다.

### 자동 검사와 발견 사항

- 계산·저장 74개 통과: EPIC 1의 46개 + EPIC 2 계산 24개·저장 4개. 날짜·8개 항목·정수 금액·0/음수/미래 거부, 출처·기존 배분기준 보존, 중복 확인, 금액 교체·귀속일 이동·삭제, 저장 실패 전체 취소·재시도·탭 충돌을 확인했다.
- 새 브라우저 기능 검사 7개 통과: 비용 편집·재실행 보관, 실제 IndexedDB 쓰기 실패·삭제 실패, 중복 취소/확인, 두 탭 충돌, 판매→수익성→손익→잔량, 필터 격리, 시작 전·미래·기록 없는 월, 모바일·키보드·외부 요청 없음.
- 날짜별 가격의 폐기 평가, 기록별 반올림, 월계획·입고대금·실사 차이 비용 중복 금지, 원가/가격 누락 시 불완전 표시, 비용만 있는 손실·0매출 비율 없음, 실사 기준과 미확정 판매 차감을 검사했다.
- 최초 브라우저 검사에서 장식 아이콘이 이동 메뉴의 접근 가능한 이름에 포함되어 정확한 이름 찾기가 실패했다. 메뉴의 접근 가능한 이름을 명시해 개선한 뒤 새 기능 7개가 모두 통과했다. 원장 계산을 바꾸지는 않았다.

- S11 입고: 날짜·재료·수량과 선택 공급사·단가를 실제 저장하고 잔량에 반영한다. 입고 금액을 매장 비용에 자동 중복 반영하지 않는다.
